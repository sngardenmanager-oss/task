# 공통 기능·인증·저장·배포 재사용 가이드

## 1. 이 문서의 용도

각 탭을 다른 프로그램에 옮길 때 함께 필요한 공통 기반을 설명한다. 현재 코드를 그대로 복사할 수 있는 부분과 먼저 분리해야 할 부분을 구분한다.

## 2. 애플리케이션 부팅

```text
app/page.tsx
  → AuthGate
    → Supabase browser client singleton
    → getSession + onAuthStateChange
    → GET /api/state
    → dynamic import WorkCalendarApp
      → 9개 탭과 공통 모달
```

`AuthGate`는 다음 gate state를 명시적으로 가진다.

- checking: 로컬 세션 확인
- signed-out: 로그인 화면
- loading: API 데이터 요청
- ready: 앱 진입 가능
- denied: 승인 대기 또는 비활성/오류

다른 프로젝트에서도 인증 상태를 boolean 여러 개로 흩뜨리지 말고 discriminated union으로 표현하면 불가능한 상태 조합을 줄일 수 있다.

## 3. 인증 구조

### 브라우저

`lib/supabase-browser.ts`는 publishable/anon 키로 singleton SupabaseClient를 만든다.

```ts
auth: {
  persistSession: true,
  autoRefreshToken: true,
  detectSessionInUrl: true
}
```

비밀번호 로그인과 가입은 브라우저 SDK가 담당한다. 획득한 access token만 Next.js API의 Bearer header로 보낸다.

### 서버

`authenticateRequest`는 Bearer token을 추출하고 공개 키 client의 `auth.getUser(token)`으로 사용자 진위를 검증한다. 이메일을 `WorkspaceState.members`와 대조하는 `requireWorkspaceMember`가 업무 권한을 결정한다.

DB 관리 작업과 Auth admin API는 `lib/supabase-server.ts`의 service role client를 사용한다. 이 client는 서버 모듈에서만 import해야 한다.

### MASTER_EMAILS

`MASTER_EMAILS`의 이메일은 workspace 멤버가 없어도 관리자 actor로 간주한다. 긴급 복구용 기능이므로 Vercel 환경변수에서만 관리하고 일반 화면에 노출하지 않는다.

## 4. 권한 검증 패턴

권한은 두 겹이다.

1. UI: `isAdmin`, `canEdit`로 버튼 숨김/비활성
2. API: 저장 전 before/after 상태 비교

`commenter`는 comments를 제외한 상태가 같아야 하며 기존 댓글 삭제도 금지한다. `member`는 members/categories 변경과 새 최종 완료를 할 수 없다. 삭제 tombstone은 admin만 제출할 수 있다.

다른 프로젝트에서는 이 로직을 다음 순수 함수로 분리하는 것이 좋다.

```ts
authorizeTransition({ actor, before, after, command }): void
```

UI 권한만으로 보안을 구현하면 안 된다.

## 5. 상태와 오프라인 병합

### 클라이언트

- `data` 하나에 members, categories, tasks, routines, notes를 둔다.
- `updateData`는 immutable updater로 상태를 바꾼다.
- 500ms debounce 후 localStorage와 서버에 저장한다.
- localStorage key는 사용자 이메일별로 분리한다.

### 병합

`mergeWorkspaceStates`와 서버 `mergeIncomingState`는 id 기준으로 배열을 합친다. 우선 상태에 같은 id가 있으면 우선 객체를 사용하고, 없는 객체는 반대편에서 보존한다. `deletedIds`에 포함된 것은 최종 결과에서 제거한다.

이 방식은 오프라인 복구와 서로 다른 항목의 동시 추가에는 유용하다. 동일 항목 동시 수정의 필드 충돌에는 충분하지 않다.

### 권장 확장

데이터 증가가 예상되면 다음처럼 관계형으로 분리한다.

```text
members
categories
tasks
task_collaborators
task_checklist_items
task_comments
routines
routine_checklist_items
routine_links
special_notes
note_comments
```

각 행에 `updated_at`, 필요하면 `version`을 두고 optimistic concurrency를 적용한다. API도 전체 state PUT 대신 command 또는 resource별 PATCH로 바꾼다.

## 6. 날짜 규칙

- 저장 형식: `YYYY-MM-DD`
- 기준 시간대: `Asia/Seoul`
- 표시 형식: `M월 D일`
- 기간 비교: 문자열 사전식 비교
- ISO timestamp: 댓글, 생성·완료 시각

날짜만 의미하는 값에 UTC timestamp를 저장하지 않는 점이 핵심이다. 다른 프로그램에서도 달력 날짜와 순간(timestamp)을 타입 수준에서 구분한다.

## 7. 공통 UI 패턴

### ModalShell

모바일에서는 하단 sheet처럼, 큰 화면에서는 중앙 dialog처럼 보인다. 배경 클릭, 닫기 버튼과 browser history를 연동한다.

### TaskCard

분류 색상, 제목, 날짜, 담당자, 상태를 한 줄 카드로 표준화한다. 오늘/전체 업무/팀 현황에서 같은 상세 모달로 연결된다.

### LinkifiedText

문장 속 http/https URL을 anchor로 변환한다. React element key, 외부 링크 보안 속성, 부모 클릭 전파 중지를 포함한다.

### Toast

별도 라이브러리 없이 문자열 상태와 2.8초 timeout으로 성공/오류 알림을 표시한다.

### 반응형 내비게이션

- 데스크톱: 좌측 sidebar
- 모바일: 하단 5개 핵심 메뉴 + 상단 햄버거 전체 메뉴
- 실제 view state는 공유

## 8. 브라우저 history

탭과 모달이 단일 URL에서 동작하므로 자체 `AppHistoryEntry`를 `window.history.state`에 기록한다. ref는 event handler가 오래된 React state를 캡처하는 문제를 피한다.

재사용할 때는 라우터 기반 URL을 사용할 수 있으면 `/tasks/:id` 같은 실제 route가 더 단순하다. Electron/단일 화면에서 Android 뒤로가기를 제어해야 하면 현재 패턴이 유용하다.

## 9. 성능 패턴

- Auth 후 본 화면 dynamic import
- 코드 preload와 API request 병렬화
- 검색 `useDeferredValue`
- task 파생 목록 단일 순회 + `useMemo`
- ExcelJS user action 시점 dynamic import
- 뉴스 10건 우선/전체 lazy load
- 뉴스 파일 snapshot 기반 재동기화 생략
- 뉴스 카드 `content-visibility:auto`
- 캘린더 다일 막대 overlay와 lane 제한

다른 프로젝트에서 가장 먼저 가져갈 수 있는 패턴은 큰 라이브러리 동적 import, 초기 화면에 필요한 최소 데이터만 요청, 파생 목록 memoization이다.

## 10. API와 저장 adapter

현재 UI 일부는 fetch URL을 직접 알고 있다. 재사용성을 높이려면 다음 adapter를 만든다.

```ts
interface WorkspaceRepository {
  load(signal?: AbortSignal): Promise<WorkspaceState>;
  save(state: WorkspaceState, deletedIds: string[]): Promise<WorkspaceState>;
}

interface AuthSessionProvider {
  getSession(): Promise<Session | null>;
  signIn(email: string, password: string): Promise<void>;
  signOut(): Promise<void>;
}
```

React 컴포넌트는 repository를 주입받으면 Supabase, Firebase, 자체 API 사이를 바꾸기 쉽다.

## 11. Electron 재사용

Electron은 웹앱 shell 역할만 한다.

```text
main.cjs
  ├─ BrowserWindow 생성
  ├─ 배포 URL loadURL
  ├─ 새 창 URL을 shell.openExternal로 전달
  ├─ 로컬 뉴스 파일 읽기 IPC
  └─ smoke-test 모드

preload.cjs
  └─ contextBridge로 허용된 두 함수만 노출
```

보안 설정은 유지해야 한다.

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`
- preload에서 임의 ipcRenderer를 통째로 노출하지 않음

다른 로컬 파일 연동 기능도 main process에서 읽고 최소 데이터만 preload API로 넘긴다.

## 12. 배포 구조 재사용

```text
GitHub main push
  → Vercel Git Integration
  → npm run build
  → Next.js Production
  → Electron이 같은 Production URL 로드
```

필요 파일:

- `vercel.json`: framework nextjs, buildCommand
- `.vercel/project.json`: 로컬 링크 전용이며 보통 Git ignore
- `desktop/site-url.json`: 데스크톱 운영 URL
- Vercel 환경변수: Supabase URL/키
- Supabase migrations: DB 테이블

환경변수 값을 Git에 넣지 않는다. 새 프로젝트로 복사할 때 기존 `.vercel`과 `.env.local`을 복사하지 말고 새 프로젝트에 `vercel link`와 새 Supabase 프로젝트 키를 설정한다.

## 13. 탭 단위 리팩터링 권장 구조

현재 5,400줄 파일을 다음처럼 나누면 기능을 옮기기 쉬워진다.

```text
features/
  dashboard/
  calendar/
  tasks/
  routines/
  notes/
  team/
  news/
  settings/
  notifications/
shared/
  auth/
  permissions/
  date/
  persistence/
  components/
```

각 feature는 `types`, `selectors`, `commands`, `components`, `tests`를 갖도록 한다. 가장 먼저 분리할 후보는 순수 계산인 달력 segment/lane, 대시보드 selector, recurrence 판정, CSV/Excel mapper다.

## 14. 검증 체크리스트

기능을 다른 프로젝트로 옮긴 뒤 다음을 확인한다.

- 로그인 만료 시 401 처리와 로그아웃
- commenter가 본문을 변경하지 못함
- member가 최종 완료하지 못함
- 시작일~종료일 다일 막대가 주 경계를 넘어 이어짐
- 같은 날 일정 과밀 시 더보기 정확성
- 루틴 nextDate 이전 미표시
- 특이사항→업무 중복 전환 방지
- CSV 한글과 큰따옴표 정상
- Excel 드롭다운과 행 변환
- Electron 외부 링크가 내부 창 대신 기본 브라우저로 열림
- 네트워크 실패 후 localStorage 복구
- 두 클라이언트 추가 항목 병합과 삭제 tombstone
