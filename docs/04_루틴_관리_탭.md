# 루틴 관리 탭 구현 문서

## 목적

주기적으로 반복되는 운영 업무를 템플릿처럼 정의하고, 캘린더에 반복 표시하거나 오늘의 실제 업무로 생성한다. 루틴 정의와 실행 이력인 `Task`를 분리하므로 루틴을 중단하거나 삭제해도 이미 생성된 업무는 유지된다.

## 관련 코드

- 목록: `RoutinesView`
- 등록/수정: `RoutineForm`, `EditRoutineForm`, `RoutineEditor`
- 상세: `InteractiveRoutineDetail`
- 반복 판정: `routineOccursOnDate`
- 링크 호환: `routineLinks`
- 실제 업무 생성용 체크리스트: `routineChecklistWithLinks`
- 체크 완료: `toggleRoutineChecklist`
- 삭제: `deleteRoutine`
- 데이터 타입: `Routine`, `ReferenceLink`, `Task`

## 데이터 구조

```ts
type Routine = {
  id: string;
  title: string;
  categoryId: string;
  assigneeId: string;
  cadence: string;
  checklist: string[];
  checklistDone?: boolean[];
  referenceLinks?: ReferenceLink[];
  active: boolean;
  nextDate: string;
};
```

체크리스트 문구와 완료 여부를 별도 배열로 보관한다. `referenceLinks`의 `afterChecklistIndex`는 링크를 첫 항목 앞(0) 또는 특정 체크 항목 뒤에 배치한다.

## 등록과 수정

`RoutineEditor`를 생성/수정이 함께 사용한다.

- 루틴명, 담당자, 분류, 반복 주기, 다음 실행일을 입력한다.
- 체크리스트는 한 줄당 한 항목으로 변환한다.
- 참고 링크는 제목, URL, 표시 위치를 지정한다.
- `normalizeUrl`이 scheme이 없는 주소에 `https://`를 붙인다.
- 수정 시 같은 위치와 같은 문구의 체크 항목은 기존 완료 상태를 유지한다.
- 과거 `referenceUrl` 단일 필드는 `routineLinks`가 `ReferenceLink[]` 형태로 변환해 호환한다.

## 캘린더 자동 표시

루틴은 DB에 매일 별도 행을 생성하지 않는다. 캘린더를 렌더링할 때 `routineOccursOnDate(routine, date)`를 계산하여 가상 일정으로 표시한다.

이 방식의 장점은 데이터가 날짜 수만큼 증가하지 않는다는 것이다. 단점은 과거 특정 날짜의 실행 여부를 루틴 정의만으로는 기록하지 못한다는 점이다.

## 오늘 실행

`RoutinesView.createToday`는 루틴 정의를 실제 `Task`로 복사한다.

- 제목·분류·담당자를 상속한다.
- 날짜는 오늘이다.
- `type='routine'`, `priority='normal'`, `status='scheduled'`다.
- 체크리스트 사이에 참고 링크를 `제목: URL` 문자열 항목으로 삽입한다.
- 이후의 체크와 댓글, 상태 변화는 일반 업무와 같은 워크플로를 사용한다.

루틴 정의와 생성된 업무 사이에 routineId 참조는 현재 저장하지 않는다. 향후 자동 실행 이력 분석이 필요하면 `sourceRoutineId`를 `Task`에 추가하는 것이 좋다.

## 중단·재시작·삭제

- 중단은 `active=false`로 바꾸며 과거 업무를 유지한다.
- 재시작은 `active=true`로 바꾼다.
- 삭제는 관리자만 가능하며 루틴 정의와 id만 제거/tombstone 처리한다.
- 삭제 확인 문구가 안내하듯 이미 생성된 업무는 지우지 않는다.

## 상세 화면

`InteractiveRoutineDetail`은 담당자, 주기, 다음 실행일, 활성 상태, 체크리스트 진행률과 참고 링크를 보여준다. 체크 항목은 팀원 이상이 토글할 수 있고 링크는 지정한 위치에 렌더링된다.

## 재사용 방법

재사용 시에는 자연어 문자열보다 구조화된 주기 모델을 권장한다.

```ts
type Recurrence =
  | { kind: 'daily'; interval: number }
  | { kind: 'weekly'; interval: number; weekdays: number[] }
  | { kind: 'monthly'; day: number };
```

이후 다음 세 계층으로 나눈다.

1. `recursOnDate(recurrence, anchorDate, targetDate)` 순수 함수
2. `RoutineTemplateEditor` 정의 편집 UI
3. `instantiateRoutine(routine, date)` 실제 Task 생성기

이 세 부분만 있으면 청소 점검, 정기 보고, 장비 관리, 콘텐츠 발행 등 다른 프로그램에도 적용할 수 있다.

## 주의할 점

- 현재 `cadence` 판정은 문구에 포함된 `매일/매주/격주/매월`만 인식한다.
- `매월`의 31일 루틴은 31일이 없는 달에 실행되지 않는다.
- 체크 완료 상태는 루틴 템플릿 자체에 저장되므로 날짜별 실행 상태가 아니다.
- 날짜별 이력이 필요하면 반드시 실제 Task를 생성해 기록해야 한다.
