# 알림 탭 구현 문서

## 목적

팀원이 완료 요청한 업무를 관리자가 최종 승인하거나 반려하는 간단한 승인함이다. 상단 종 모양 badge와 같은 데이터를 사용한다.

## 관련 코드

- 화면: `NotificationsView`
- 상단 badge: `completionRequests`
- 상태 변경: `setTaskStatus`
- 상세 보기: `openTask`, `TaskDetail`
- 서버 권한: `app/api/state/route.ts`의 `validateUpdate`

## 목록 생성

```ts
requests = data.tasks.filter(
  task => task.status === 'completion_requested'
)
```

각 행은 제목, 시작일, 담당자를 보여준다. 제목 영역을 누르면 업무 상세 모달을 연다.

## 승인 흐름

- 반려: `completion_requested → in_progress`
- 최종 완료: `completion_requested → completed`
- 버튼은 관리자에게만 표시된다.
- 비관리자가 조작 요청을 만들어 보내도 서버가 새 completed 상태를 감지해 403으로 거절한다.

상단 종 아이콘의 숫자도 동일한 `completionRequests.length`를 사용하므로 별도 알림 테이블이나 읽음 상태는 없다.

## 현재 의미

이 탭의 알림은 push notification이 아니라 업무 상태에서 실시간으로 계산한 작업함이다.

- 읽음/안 읽음 없음
- 이메일·모바일 푸시 없음
- 담당 관리자 지정 없음
- 완료 요청 생성 시각 별도 없음
- 정렬은 현재 tasks 배열 순서

## 재사용 방법

다른 승인 프로그램에서는 범용 상태 전이 요청으로 모델링할 수 있다.

```ts
type ApprovalRequest = {
  id: string;
  subjectId: string;
  requestedBy: string;
  requestedAt: string;
  state: 'pending' | 'approved' | 'rejected';
  reviewerId?: string;
  reviewedAt?: string;
  reason?: string;
};
```

현재처럼 원본 업무 상태만으로 계산하는 방식은 단순하지만 승인 이력과 처리 시간을 분석할 수 없다. 감사 기록이 필요하면 별도 ApprovalRequest 테이블이 적합하다.

## 확장 아이디어

- 요청 시간순/긴급순 정렬
- 반려 사유 댓글 필수
- 관리자별 담당 큐
- 브라우저 알림 또는 이메일 알림
- 승인 이력과 평균 처리 시간
- badge의 읽음 상태

## 주의할 점

- 완료 요청 수는 전체 팀 기준이며 사용자별 필터가 없다.
- 관리자 한 명이 처리하면 공유 상태가 저장되어 모든 사용자 화면에서 사라진다.
- 네트워크 실패 시 로컬에서 먼저 상태가 바뀔 수 있으므로 저장 실패 toast를 확인해야 한다.
