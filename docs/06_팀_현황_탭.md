# 팀 현황 탭 구현 문서

## 목적

활성 사용자별 미완료 업무량과 완료 요청 수를 빠르게 비교하고, 각 사용자의 대표 업무를 열어보는 화면이다.

## 관련 코드

- 화면: `TeamView`
- 사용자 표시: `roleLabel`
- 업무 상세: `openTask`, `TaskDetail`
- 데이터: `WorkspaceState.members`, `WorkspaceState.tasks`

## 계산 방식

활성 멤버마다 전체 업무를 필터링한다.

```ts
assigned = task.assigneeId === member.id && task.status !== 'completed'
requests = assigned.filter(status === 'completion_requested')
```

카드에는 이름 첫 글자 아바타, 소속, 권한, 진행 업무 수, 완료 요청 수와 앞의 업무 3개를 보여준다. 업무 제목을 누르면 공통 `TaskDetail` 모달을 연다.

## 현재 집계 기준

- 주담당자 `assigneeId`만 집계한다.
- `collaborators`에 포함된 협업 업무는 계산하지 않는다.
- 완료 상태는 진행 업무 수에서 제외한다.
- 일정 기간 필터 없이 전체 미완료 업무를 센다.
- 카드의 업무 3개는 별도 정렬 없이 현재 tasks 배열 순서를 따른다.

## 권한

팀 현황 자체는 모든 승인 사용자가 볼 수 있다. 카드에서 상세를 연 뒤 가능한 행동은 `TaskDetail`의 공통 권한을 따른다.

## 재사용 방법

다른 프로그램에서는 selector를 UI와 분리한다.

```ts
type MemberWorkload = {
  member: Member;
  activeCount: number;
  completionRequestCount: number;
  urgentCount: number;
  overdueCount: number;
  sampleTasks: Task[];
};
```

`buildMemberWorkloads(members, tasks, options)` 순수 함수를 만들면 영업 담당자, 프로젝트 구성원, 시설 점검 담당자 화면에 그대로 쓸 수 있다.

## 확장 아이디어

- 협업자 포함/제외 토글
- 지연 업무와 긴급 업무 지표
- 팀/소속별 그룹핑
- 특정 기간의 완료율
- 업무량 기준 정렬
- 담당자 없는 업무 별도 카드

## 주의할 점

- 현재 수치는 업무 난이도나 기간을 반영하지 않는 단순 건수다.
- 협업 업무가 많은 구성원은 실제보다 업무량이 적게 보일 수 있다.
- 사용자 퇴사 처리는 팀 현황이 아니라 설정 탭에서 수행한다.
