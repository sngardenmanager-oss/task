# 보고 기록과 연결 업무 고도화 운영 안내

적용 기준: 2026-10-06. 전체 개선 방향은 `19_보고체계_기록관리_및_연결업무_고도화_기획서.md`를 참고합니다. 이 문서는 이번 구현 범위와 실제 사용 방법을 설명합니다.

## 보고서를 제출하고 확정하는 방법

1. **보고서**에서 기존 방식으로 내용·실적·계획·통계를 작성하고 **초안 저장**을 누릅니다.
2. **보고 제출과 처리 기록**에서 검토자와 최종 확정자를 선택하고 **보고 제출**을 누릅니다. 최종 확정자는 활성 관리자여야 합니다. 제출자 본인이 확정자이면 예외 사유가 필요합니다.
3. 지정 검토자는 **검토 시작**, **보완 요청**, **검토 완료**를 처리합니다. 보완 요청에는 사유가 필요합니다. 보완 요청 후 작성자가 수정·저장하고 재제출할 수 있습니다.
4. 검토 완료 후 지정 관리자가 **최종 확정**합니다. 제출자 또는 관리자는 확정 전 사유를 남겨 **제출 철회**할 수 있습니다.
5. 확정 내용을 바꿔야 하면 **정정본 작성**을 사용합니다. 새 번호와 수정 차수로 작성하고 정정 사유를 남겨 다시 제출합니다. 원래 확정본은 유지됩니다.

제출할 때 보고 내용, 통계 및 입도객 계산 자료, 연결 프로젝트 현황을 고정합니다. 제출 중인 보고서는 보완 요청·철회 전까지 수정할 수 없습니다. 처리 시각, 처리자, 의견, 제출 횟수를 **처리 이력**에서 확인합니다. 과거에 작성한 확정본은 당시 승인 이력이 없다는 사실을 표시합니다.

## 연결된 업무와 후속 조치

- 보고서의 **연결 프로젝트 현황**에서 상위 업무와 직접 연결된 하위 일정, 최종 완료·완료 요청·기준일 대비 지연 수를 확인합니다. **현재 업무와 비교**로 제출 당시와 현재 상태를 전환합니다.
- 업무 상세의 **업무 흐름과 기록**에서 상위·하위·선행·후행·관련 업무를 열고 변경 이력을 조회합니다. 순환 연결은 중복 표시하지 않습니다.
- 확정 보고서의 **회의 결정과 후속 조치 → 결정 등록**에서 관리자가 결정 내용, 담당자, 기한, 사유를 남깁니다. 기존 업무를 연결하거나 새 후속 업무를 함께 생성할 수 있습니다. 결정과 새 업무는 하나의 DB 트랜잭션으로 저장합니다.
- 담당자는 조치 결과와 근거 링크를 남기고, 관리자는 결과를 확인한 뒤 **결과 확인 후 종료**로 마감합니다. 결정 변경 전후 내용도 별도 이력으로 보관됩니다.

## 기록 검색과 보관

**보고·업무 기록** 탭에서 보고서 장기 보관함과 변경 기록을 조회합니다. 검색어·대상 종류·기간으로 기록을 좁히고 상세에서 변경 전후 내용을 확인할 수 있습니다. 보고 기록에는 당시 내용을 이용한 Excel/PDF 출력도 제공합니다.

업무·메모·루틴, 보고서·통계·입도객 자료, 결정 변경 기록은 원본 저장과 같은 트랜잭션에서 생성됩니다. 서버가 확인한 사용자와 DB 시각을 사용하며 일반 앱 계정으로 기록을 수정·삭제할 수 없습니다. DB 운영자 권한을 가진 관리자의 직접 조작까지 방지하는 외부 감사 시스템은 아닙니다.

확정본은 별도 장기 보관함에 보존됩니다. 정기 백업 후 활성 목록에서 정리하더라도 조회할 수 있습니다. 업데이트 이전에 이미 삭제된 자료는 자동 복구되지 않으며, 남아 있는 기존 확정본만 초기 보관 대상입니다.

마스터의 전체 백업 JSON에는 활성·비활성 팀의 원본 자료와 변경 기록, 확정본, 결정사항 및 통합 회의본이 포함됩니다(`schemaVersion: 2`). 기존 Excel 백업도 유지합니다. 대규모 파일 첨부와 자동 복원 UI는 이번 범위에 포함하지 않습니다.

## 통합 회의본

마스터의 통합 보고 화면에서 현재 자료를 확인한 뒤 회의본을 확정·보관할 수 있습니다. 미확정 팀 자료가 있으면 예외 사유가 필요합니다. 화면을 연 후 자료가 바뀌면 확정을 막고 새로 확인하도록 안내합니다. 과거 회의본을 열면 당시 팀 보고 번호·수정 차수와 내용을 사용합니다. 활성 목록에서 정리한 팀 확정본도 해당 주의 통합 보고 조회에 포함합니다.

## 배포·검증 참고

- DB 변경: `supabase/migrations/0007_reporting_records.sql`. `scripts/migrate-report-records.mjs --status`로 적용 여부를 확인할 수 있습니다. 인자 없는 실행은 검증 후 롤백하고, `--apply`만 반영합니다.
- 자동 검증: 보고 처리 권한·순서·동시 수정·재시도, 제출 시점 자료 보존, 확정본 수정 차단, 팀 접근 범위, 원본과 이력의 동시 저장을 검증합니다.
- `scripts/verify-report-records.mjs`는 격리된 임시 계정·팀으로 실제 UI와 API를 검증하고 임시 자료를 정리합니다. DB 연결 정보는 로컬 환경변수에서만 읽습니다.
- 프로그램의 기존 설치 파일은 운영 웹사이트를 불러오는 방식이므로 운영 배포 후 새로고침 또는 재실행하면 반영됩니다.

조직 전체의 다단계 결재선 설정, 팀 간 세부 공유 정책, 자동 알림·독촉, 첨부파일 버전 관리, 자동 복원 화면은 후속 확장 항목입니다. 이번 구현은 보고별 검토자·확정자 지정, 변경 기록 보존, 연결 업무 조회 및 결정 후속 조치에 집중합니다.
