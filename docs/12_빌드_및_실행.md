# 빌드 및 실행

2026-09-20 기준. 프로젝트 폴더에서 다음 명령을 실행한다.

## 빌드 명령

| 대상 | 명령 | 결과 |
|---|---|---|
| 웹 | `npm run build` | `.next/` 프로덕션 출력 |
| Windows | `npm run desktop:build` | `desktop-dist/스누피가든-업무캘린더-0.1.0.exe` |
| Android 설치용 | `npm run android:build:release` | `android-dist/스누피가든-업무캘린더-release.apk` |
| Android 개발용 | `npm run android:build` | `android-dist/스누피가든-업무캘린더-debug.apk` |

## Windows 빌드

`scripts/build-desktop.mjs`가 전용 임시 프로젝트에 `desktop/` 실행 파일과 최소한의 package.json을 복사하고 Electron portable 실행 파일을 만든다. 웹 프로젝트의 Next.js 및 서버 의존성을 함께 패키징하지 않는다. Electron 버전은 설치된 패키지를 따르고 앱 버전·아이콘·출력 이름은 프로젝트의 package.json을 따른다. 임시 경로는 빌드 로그에서 확인할 수 있다.

## Android 빌드

JDK 21과 Android SDK가 필요하다. `JAVA_HOME`, `ANDROID_HOME` 또는 `ANDROID_SDK_ROOT`로 도구 경로를 지정할 수 있다. 별도 설정이 없으면 기존 이 컴퓨터의 설치 위치를 사용한다.

Capacitor 동기화 후 Android 프로젝트와 Capacitor Android 라이브러리만 새 임시 폴더에 복사한다. 한글 경로 때문에 Gradle 빌드가 실패하지 않도록 임시 경로는 영문 경로를 사용한다. 필요하면 `SNOOPY_ANDROID_TEMP`를 지정한다. 기존 폴더를 미러링하거나 삭제하지 않는다.

설치용 빌드는 기존 `android/keystore.properties`와 해당 서명 키를 사용한다. 키와 비밀번호는 버전 관리에 넣지 않는다.

## 웹 서비스 반영

Windows 앱과 Android 앱은 설정된 Vercel 웹 주소를 여는 앱이다. 로컬 웹 빌드 결과를 설치 파일에 포함하지 않는다. 보고서 기능 등 웹 변경 사항을 앱에 반영하려면 기존 Vercel 서비스에 별도로 배포해야 한다.

- Windows 웹 주소: `desktop/site-url.json`
- Android 웹 주소: `capacitor.config.ts`
- 운영 배포는 GitHub `main` 브랜치에 반영하면 기존 Vercel 연동으로 진행된다. 배포 완료 뒤 열려 있는 앱을 새로고침하거나 다시 실행한다.
